# SQL 对比计算列表达式自动别名与可追溯展示

## 背景与根因

SQL 数据对比允许用户把查询结果作为源表或目标表。当前预览接口直接采用数据库
`cursor.description` 返回的列名，Worker 随后把任务保存的列名拼成外层选择列表。

故障任务的两侧 SQL 都有 8 个投影项，其中第 6～8 项为未指定 `AS` 别名的
`SUM(...)`。DB2 把这三个投影报告为 `6`、`7`、`8`，前端带入后又将它们保存为
比较列。最近 5 次运行均以 `sql_failed / Db2AdapterError` 结束，所以页面看到的
“无结果”实际是查询失败，不是零差异。

数据源当前不可连接。本修复以已持久化的任务元数据、SQL 投影结构、运行记录和
Worker 日志为复现证据；不声称完成真实 DB2 联调。

## 用户体验

用户写普通列时行为不变：

```sql
SELECT CUST_NO, SEC_CODE FROM T
```

用户给表达式显式命名时优先使用用户名称：

```sql
SELECT SUM(AMOUNT) AS TOTAL_AMOUNT FROM T
```

未命名的计算表达式由系统按投影顺序生成稳定名称：

```sql
SELECT
    CUST_NO,
    CASE WHEN BALANCE > 0 THEN 'Y' ELSE 'N' END,
    SUM(AMOUNT)
FROM T
GROUP BY CUST_NO, CASE WHEN BALANCE > 0 THEN 'Y' ELSE 'N' END
```

对应列显示为 `CUST_NO`、`RESULT_1`、`RESULT_2`。编号只统计需要生成名称的表达式，
并跳过与已有列名或显式别名大小写不敏感冲突的名称。例如查询已经包含
`RESULT_1` 时，第一个自动名称使用 `RESULT_2`。

自动名称旁显示信息图标：

- 悬停显示单行截断摘要，不撑开表格。
- 点击名称或图标打开浮层，显示格式化后的完整投影表达式、原始投影位置和
  “系统生成别名”标记。
- 完整表达式放在可横向/纵向滚动的等宽代码框中，并提供复制按钮。
- 键盘用户可聚焦并用 Enter/Space 打开，浮层具备可访问名称。

预览表头、列配置和对比结果表头使用同一展示组件或同一元数据查找逻辑，避免同一列
在不同区域表现不一致。用户原始 SQL 不被界面覆盖。

## SQL 规范化

新增一个无 IO 的领域函数，输入只读 SQL 和数据库类型，输出：

1. 供数据库执行的规范化 SQL；
2. 按投影顺序排列的列描述元数据；
3. 是否修改过投影别名。

只对最外层 `SELECT` 的下列未命名表达式生成别名：聚合函数、`CASE`、一般函数、
算术/字符串运算、类型转换及其他非简单列投影。简单 `table.column` 保持原名，已有
显式别名保持不变，`*`/`table.*` 保持数据库展开行为。

生成的内部 SQL 使用 `sqlglot` AST 增加 `AS RESULT_n`。预览、主键预检和 Worker
的 SQL 对比读取器必须调用同一函数，不能各自实现一套规则。这样预览带入的
`RESULT_n` 在正式运行时一定是子查询中可引用的真实别名。

第一版自动改写只覆盖可可靠定位输出列的单个最外层 `SELECT`（允许前置 CTE）。
`UNION` 等集合查询或 DB2 私有语法若无法可靠解析，不改写用户 SQL，并返回明确、
脱敏的“请为计算列显式添加 AS 别名”错误；不得退回数据库生成的纯数字列名，也
不得按位置静默猜测。已有显式别名的方言特有 SQL 不因自动别名功能被无条件拒绝，
仍可沿用原执行路径。

## API 与元数据

`ComparePreviewResponse` 追加可选字段 `column_details`，保持现有 `columns: string[]`
向后兼容。每项包含：

```json
{
  "name": "RESULT_1",
  "generated": true,
  "projection_index": 6,
  "expression": "CASE WHEN ... END"
}
```

普通列也可返回详情，但 `generated=false` 且无需返回冗长表达式。前端在字段缺失时按
旧响应正常工作。

任务查询响应根据已保存的 `source_ref.sql` 和 `target_ref.sql` 计算同样的投影元数据，
让页面刷新、历史任务和结果区域仍能解释 `RESULT_n`，避免新增数据库迁移。表达式内容
仅返回给已有权限的任务访问者，不进入审计详情或应用日志。

创建或更新 SQL 对比任务时，对 SQL 做相同的可解析性检查，但继续保存用户原始 SQL。
Worker 每次运行从原始 SQL 确定性生成内部 SQL，避免旧客户端绕过预览后再次保存
`6/7/8`。

## 旧任务兼容

不批量修改历史任务，也不在数据库中覆盖原 SQL。

打开旧 SQL 任务时，后端重新推导生成别名。若任务列仍是 DB2 产生的纯数字名称，
页面提示“检测到旧版未命名计算列”，并提供一次确认式“更新为 RESULT_n”操作；操作
同时更新主键、忽略列和目标映射中的引用。正式运行前若仍存在无法对应的旧数字列名，
后端拒绝入队并返回明确错误，不能再生成一个必然失败且结果为零的运行记录。

旧任务转换只在“该序号对应的 SQL 投影确定是未命名计算表达式，且数字名称等于驱动
返回的投影序号”时提供。用户显式写出的合法数字别名不自动修改，避免误伤。

本次故障任务在部署新版本后通过该确认操作把第 6～8 列更新为 `RESULT_1`～
`RESULT_3`。由于数据源不可连接，只验证任务配置转换和生成 SQL，不触发真实运行。

## 错误与安全

- 页面必须把失败运行显示为“执行失败”，不能用全零桶伪装成“无差异”。
- Worker 日志只记录错误类型、任务/运行标识和投影数量，不记录原 SQL、完整表达式、
  行数据、连接信息或驱动原始消息。
- 表达式可能含业务字面量；悬停只显示受长度限制的摘要，完整表达式仅在用户主动点击
  后展示。
- API 错误保持通用文案，结构化错误可包含投影序号，但不能回显原始表达式。

## 测试与验收

先写失败测试，再实现：

1. 领域单元测试：普通列、显式别名、`SUM`、长 `CASE`、函数/运算、名称冲突、
   大小写冲突、CTE、`*`、解析失败及两次规范化幂等。
2. Worker 单元测试：SQL 子查询使用规范化后的 `RESULT_n`，外层选择、排序和映射能
   引用生成别名；不再引用 `"6"`、`"7"`、`"8"`。
3. API 契约测试：预览继续返回 `columns`，追加 `column_details`；任务保存原始 SQL；
   非只读 SQL和无法规范化的 SQL 返回脱敏错误。
4. 前端测试：自动名称带信息图标，悬停有摘要，点击显示完整表达式；旧响应无详情时
   不崩；失败运行不会显示成成功的零结果。
5. 质量检查：相关 pytest、全量 pytest、ruff、mypy、前端 typecheck/build、
   `make check-redlines` 和敏感信息扫描。
6. 浏览器验证：打开真实 compare 页面，确认首屏、Console、Network、预览列配置及
   表达式浮层。由于当前数据源不可连接，真实 DB2 预览和运行标记为未验证；使用已有
   故障任务的保存数据验证旧任务转换，并使用测试适配器覆盖执行 SQL。
